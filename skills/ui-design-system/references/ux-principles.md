# UX 原则

## 第一条：可用性是成本，不是偏好

不要问"这个设计好不好看"，要问：用户要多花多少**理解成本、记忆负担、操作次数、错误率**。任何一个下降都是收益，都是可以拒绝一个"更好看"方案的正当理由。

## Nielsen 10 条实用守则（本项目相关性排序）

| 守则 | 在本项目里的具体表现 |
|---|---|
| **系统状态可见** | AI 生成中必须有进度反馈；存档保存中/已保存要可见；长列表加载要有骨架或进度 |
| **贴近真实世界** | 用"世界卡 / 世界书 / 记忆 / 事件"这些领域词，不要用"实体 / 数据集 / 记录" |
| **用户可控与自由** | 每个面板都有出口；破坏性操作可撤销或二次确认；Escape 能关覆盖层 |
| **一致性与标准** | 同级组件用同一套标记与尺寸；同一概念用同一个词 |
| **错误预防** | 删存档 / 删世界卡 / 覆盖导入 必须二次确认；输入框加约束而不是事后报错 |
| **识别而非回忆** | 显示当前选中的世界/预设，不要让用户记住自己选过什么 |
| **灵活与高效** | 高频路径要短；但不要为效率牺牲可发现性 |
| **美观与极简** | 不显示当前用不到的信息；但**不要为了简洁砍掉游戏状态** |
| **帮助用户识别、诊断、恢复** | 错误信息说清：哪里错、为什么、怎么修 |
| **帮助与文档** | 复杂功能（世界卡扩展、正则脚本）要有就地说明，不要只放在外部文档 |

## 几条最相关的 UX 定律

- **Fitts 定律** —— 目标越远越小越难点。移动端主要操作要给足命中区（≥ 44px），并把高频操作放在拇指可达区。
- **Hick 定律** —— 选项越多决策越慢。设置项分组、渐进披露；世界书条目列表不要一次全展开。
- **Miller 定律** —— 工作记忆约 7±2 项。导航分组控制在 5–7 个；状态面板不要一次抛 12 个数字。
- **Jakob 定律** —— 用户假设你的产品跟别的产品一样。常规模式（列表/详情、抽屉、弹窗）照常做，不要发明新交互。
- **Tesler 定律** —— 复杂度守恒。你把复杂度从界面藏起来，它就得在别处（默认值、自动化、更好的信息架构）被消化掉。藏起来不管 = 复杂度转嫁给用户。
- **Peak-End** —— 体验由峰值和结尾决定。会话结束、存档保存这类"结尾时刻"值得多花心思。

## 本项目的三条特有原则

1. **不要打断叙事上下文。** 读对话正文时，任何弹窗/跳转/整屏刷新都是干扰。能用内联展开就不要弹窗。
2. **游戏状态优先于装饰。** 玩家需要知道"我在哪、我有什么、发生了什么"。这些信息的可见性高于任何视觉效果。
3. **长内容是一等公民。** 世界书条目、提示词、AI 输出都可能非常长。设计时必须假设内容会撑满、会溢出、会是任意语言。

## 常见反模式

- 假设"用户会习惯的" —— 首次困惑就是缺陷
- 错误信息太抽象（"操作失败"）—— 无法指导下一步
- 把无障碍留到最后做 —— 会导致返工或直接不做
- 用弹窗解决所有问题 —— 上下文丢失
- 为主流程优化，忘了空/错/慢三种状态

## 评审清单

- [ ] 用户在这个界面要完成的一件事是什么？一步能说清吗？
- [ ] 他需要记住什么？（能改成"显示出来"吗）
- [ ] 有哪些地方可能出错？出错了信息够不够指导修复？
- [ ] 空状态、加载中、失败态都设计了吗？
- [ ] 这个操作值得打断用户吗？（还是可以内联？）
- [ ] 键盘用户能完整走完主流程吗？
