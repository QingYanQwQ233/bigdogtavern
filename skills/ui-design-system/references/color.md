# 颜色与主题

## 前提：颜色不是你的，是世界卡的

本项目有 **15+ 个主题 token**，World Card 可以覆盖其中大部分。这意味着：

> **组件设计不得依赖某一组具体颜色值。** 你只能依赖"角色的相对关系"。

角色关系是稳定的：背景比面板暗、面板比文字暗、accent 是全页唯一的强调色。具体数值不稳定。

## token 角色的使用规则

| 角色 | 用在哪 | 不要用在哪 |
|---|---|---|
| 背景层（`--bg-0` 等） | 页面底、对话框底 | 卡片、控件 |
| 面板层（`--panel` / `--panel-2`） | 侧栏、弹窗、卡片 | 文字 |
| 文字层 | 正文、标签 | 大面积填充 |
| accent（`--accent`） | **唯一的主操作**、选中态、焦点 | 装饰、多个并排元素 |
| 语义色（成功/警告/危险） | 状态提示 | 装饰 |

**accent 是全页稀缺资源。** 一屏出现两个 accent 元素，其中一个必然应该是次要样式。

## 对比度要求

- 正文文字与背景：≥ 4.5:1
- 大字号（18px 以上或 14px 粗体）：≥ 3:1
- 非文字的界面轮廓（边框、图标）：≥ 3:1

**但注意**：因为世界卡可覆盖主题，**你不能只靠对比度兜底**。文字颜色必须继承 token，不能写死。

## 主题覆盖的安全边界（硬约束）

世界卡传入的主题值必须通过校验，**禁止**出现：

- 尖括号（防标签注入）
- 花括号（防 CSS 结构逃逸）
- 分号（防声明注入）
- `url(`（防外链资源，违反离线约束）

新增任何主题 token 时，都必须同步进这套校验。

## 语义色与装饰色的区分

- **语义色**必须携带含义，且含义不能用颜色单独承载（色盲用户）。红 + 图标/文字。
- **装饰色**不应传达信息。渐变、光晕、背景纹理都属于装饰，可以随意替换。

## 已知债

token 命名法存在两代混用：

- 第一代：序号式（`--bg-0`、`--panel-2`）
- 第二代：语义式（契约里已经承诺但未落地）

**新增 token 时优先用语义式命名**，并尽量引用现有 token 而不是再造序号。迁移是独立任务，不要顺手做。

- [ ] 换一套主题色，这个组件会坏吗？
- [ ] 状态色是不是只靠颜色传达？
- [ ] 新增的主题值过安全校验了吗？
