# 信息架构与导航出口契约

本文件定义 BigDogTavern 的层级模型与**出口（exit）语义**。它是"部分页面没有退回上级按钮"这个问题的正式解。

## 层级模型

`public/index.html` 里每个区域带 `data-ui-level` 1–4。实测分布：

| 层级 | 数量 | 含义 | 需要出口吗 |
|---|---|---|---|
| L1 | 5 | app shell、侧栏、覆盖层 | **不需要**（顶层） |
| L2 | 7 | 功能根区域（管理器 / 世界库） | 需要 |
| L3 | 20 | 列表列 / 编辑列（`.sidebar` / `.editor`） | 需要 |
| L4 | 4 | 子面板（prompt entry / lore entry） | 需要 |

合计 36 个区域。**当前有 14 个区域没有出口控件** —— 这是已知偏差，不是设计意图。

## 出口的三种语义

区分出口靠的是**目标由什么决定**，不是靠文案：

| 标记 | 语义 | 目标怎么来 | 典型文案 |
|---|---|---|---|
| `data-nav-up` | 回到父级（结构，与路径无关） | 由容器层级反查 | 回到对话 / 返回工作台 / 返回世界库 |
| `data-nav-step` | 回到上一步（时序，依赖路径） | 由流程状态决定 | 返回调整基本信息 / 返回开局配置 |
| `data-overlay-close` | 关闭覆盖层 | 关掉最近的覆盖层容器 | 关闭 |

**Up 与 Step 不是同一种东西。** Up 是层级导航（我在哪 → 我去父级），即使你从别处跳进来，Up 的目标也不变。Step 是历史导航（我刚做了什么 → 撤销那一步），目标取决于你走过的路径。把两者混成一种文案是当前文案不统一的根因。

### 历史遗留映射（迁移依据）

原来的 7 种出口机制归并成 3 种：

- `data-manager-back` + `data-back-chat` + `data-world-manager-back` + `data-rpg-drawer-close` → `data-nav-up`
- `#cw-back-2` + `#rpg-extension-setup-exit` → `data-nav-step`
- `data-close` + `#debug-close` → `data-overlay-close`

注意保留 `class="back-action"` 与 `class="rpg-drawer-close"` —— CSS 依赖它们，标记迁移不碰 class。

## 出口五条硬规则

1. **非顶层区域必须有且仅有一个出口。** 层级一旦进入 L2 以下，用户必须能原路离开。
2. **出口永不禁用。** 数据没加载完、请求失败、列表为空 —— 都不构成禁用出口的理由。禁用出口等于把用户关在页面里。
3. **标签由目标反查，不由来源手写。** 文案从"我要去哪"推导，不是每个按钮各写各的。写死 `data-parent-label` 会导致同一层级出现不同说法。
4. **位置在两端一致。** 桌面端与移动端的出口放在同一个逻辑位置（区域头部左侧），只有断点行为不同 —— 当前两套 head 各自维护是债。
5. **覆盖层叠覆盖层时，Close 作用于最上层。** 与 Escape 键的处理顺序必须一致。

## 现有的可复用实现（不要从零设计）

- `handleManagerBack(button)` —— 已经在按面板状态动态决定目标：移动端详情态退回列表，否则回对话
- `syncMobileManagerBackLabel(managerId)` —— 按视口和面板层级动态改写标签
- `setMobileManagerPanel()` / `setMobilePromptPanel()` / `setMobileLorePanel()` —— 面板状态机
- `switchView(name)` —— 视图切换入口

**要做的不是发明新机制，是把已有机制提升成契约。**

## 边界场景（必须各自有兜底）

| 场景 | 正确行为 |
|---|---|
| 父级不可达 | Up 降级为"回到对话" |
| 深链进入（如 `?worldDraft=`） | 必须有兜底出口，不能只依赖历史栈 |
| 移动端抽屉已开 | 抽屉关闭优先于管理器返回 |
| 覆盖层叠覆盖层 | Close 关闭最上层 |
| 数据未加载完 | 出口保持可用 |
| 列表为空 | 显示空状态，出口保持可用 |

## 响应式行为

| 断点 | 导航形态 | 内容形态 |
|---|---|---|
| ≥ 961（桌面） | 常驻侧栏 | 两栏（列表 + 详情） |
| 641–960（平板） | 抽屉 | 两栏 |
| ≤ 640（移动） | 抽屉 | **单栏切换**（list ⇄ detail） |

移动端单栏切换依赖 `dataset.mobilePanel` 状态；`data-nav-up` 在详情态必须退回列表，而不是直接回对话。

## 评审清单

- [ ] 这个区域是顶层吗？不是的话有出口吗？
- [ ] 出口用的是 Up 还是 Step？判据是"目标由层级决定"还是"由路径决定"？
- [ ] 出口会因为任何原因被禁用吗？
- [ ] 标签是推导的还是手写的？同层级其他区域的标签一致吗？
- [ ] 移动端详情态点它会退到正确的一层吗？
- [ ] 键盘用户能到达并触发它吗？（Tab → Enter）
