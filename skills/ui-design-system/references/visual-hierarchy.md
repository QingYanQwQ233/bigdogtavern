# 视觉层级

层级回答一个问题：**用户第一眼看到什么，第二眼看到什么，什么可以等到需要时再看到。**

## 决定层级的七种手段（按推荐顺序）

1. **位置** —— 左上/顶部在多数阅读方向里优先。最便宜的层级手段。
2. **留白** —— 周围空白越多越突出。比放大字号更有效，也更不破坏节奏。
3. **尺寸** —— 有效但容易失控，且会级联影响行高与布局。
4. **字重** —— 同一字号下 400 → 600 的提升通常够用，不必换字号。
5. **对比** —— 前景/背景反差。在深色主题里尤其有效。
6. **色彩** —— 用 accent 强调，**只给一个东西用**。到处都强调 = 没有强调。
7. **动效** —— 最后手段。动的东西一定被先看到，也一定更烦人。

## 三条硬规则

1. **每个界面只有一个主操作。** 视觉上最强的那一个按钮，语义上也必须是主操作。出现两个"看起来都像主按钮"的元素就是缺陷。
2. **不要用层级表达重要性以外的信息。** 例如用大小表示"新消息"、用颜色表示"未读"——这些应该由明确的标记承担。
3. **层级必须能在灰度下成立。** 把界面转成灰度，如果层级塌了，说明过度依赖颜色。

## 分组与对齐

- **邻近性** —— 间距是分组信号：组内间距必须明显小于组间距。本项目用 2px 基尺度，组内常用 4/6/8，组间常用 12/16/20。
- **对齐** —— 每一列内容要有共同左边缘。不要用居中来解决对齐问题。
- **闭合性** —— 用背景差异或边框暗示分组时，两者只用一个。背景 + 边框 + 阴影三件套是过度设计。

## 密度

本项目是信息密集型的（管理器面板、世界书条目、提示词顺序）。密度需要**分级**而不是全局统一：

| 密度 | 场景 | 特征 |
|---|---|---|
| 紧凑 | 列表项、导航项 | 单行、次级信息隐藏或极简、行高小 |
| 标准 | 表单、设置面板 | 每项一行标签 + 控件 |
| 宽松 | 对话正文、世界卡详情 | 大行高、宽边距、允许长段落 |

**同一屏里混用超过两档密度就是层级问题。**

## 本项目特有的层级约束

- **对话正文永远是最强层级。** 任何 chrome（工具栏、状态条、徽标）的视觉强度都不得超过正文。
- **游戏状态可以常驻，但不能抢戏。** 用次级层级的常驻区域承载，不要用大色块。
- **世界卡可以覆盖视觉。** 因此不要设计"必须靠某个特定颜色才能读出层级"的组件。

## 评审清单

- [ ] 这个界面第一眼看到的是什么？是不是我们想要的那个？
- [ ] 有几个元素在争抢注意力？超过 2 个就是问题。
- [ ] 灰度下层级还成立吗？
- [ ] 主操作在视觉上唯一吗？
- [ ] 组内/组间间距有区分吗？
- [ ] 一屏里混了几档密度？
