# 无障碍

契约本体在 `docs/ui-beauty-declaration.md §7`，那里每条都标注了验证方式。本文件是设计时的执行要点。

## 验证方式有三种标注，含义不同

| 标注 | 含义 |
|---|---|
| `[静态]` | 能从源码证明，`scripts/check_ui_accessibility.js` 随 `run_checks` 自动守 |
| `[运行时]` | 只能测量，改 UI 后手动跑 `scripts/audit_ui_accessibility.js`，报告里要给数 |
| `[未强制]` | 有原因没做成自动检查，改动时要人工确认 |

**改了 UI 就跑一次 `[运行时]` 那部分并给数字**，不要只说"检查过了"。

## 八条要点

1. **命中区** —— 主要操作 ≥ 44×44。导航项有意做窄是例外（见 `responsive.md`）。
2. **移动端表单字号 ≥ 16px** —— 防 WebView 聚焦自动缩放。已统一。
3. **Escape 必须能关覆盖层** —— 所有弹窗（含设置、地图、终端）都必须在 Escape 处理链里，且按**最上层优先**关闭。
4. **关闭后焦点归还给触发者** —— 打开弹窗前的那个元素要拿回焦点。归还时**必须排除 `document.body`**：JS 触发的 `.click()` 不移动焦点，`activeElement` 可能是 body，把焦点"还"给 body 等于没还。
5. **焦点必须可见** —— 双轨模式：按钮走 `:focus-visible` + `outline`，输入框走 `:focus` + `box-shadow`。现有 6 处 `outline: none` 全部有配对指示，不要新增没有配对的。
6. **语义元素优先** —— 能用 `button` / `label` / `input` 就不要用 `div` + `role`。ARIA 是补丁，不是首选。
7. **图标按钮必须有名字** —— 可见文字优先，其次 `aria-label`。屏幕阅读器读不到符号。
8. **动态内容要播报** —— AI 生成完成、保存成功/失败用 `aria-live`，但不要滥用（每次按键都播报是灾难）。

## 键盘基线

任何界面必须能用键盘走完主流程：

- Tab 能到达所有可操作元素
- 顺序符合视觉阅读顺序（不要用 `tabindex` 强行改序）
- Enter / Space 触发
- Escape 退出当前层
- 焦点不会掉进不可见的元素

`tabindex="0"` 尽量不用；`tabindex="-1"` 只用于程序化移焦。

## 反模式（禁止）

- 用 `div` + `onClick` 当按钮（键盘不可达，角色丢失）
- 用 `role="button"` 绕过原生元素
- 到处加 `aria-label`（可见标签已存在时会导致重复播报）
- 去掉焦点环且不给替代
- 只靠颜色传达状态
- 用 `placeholder` 代替 `label`
