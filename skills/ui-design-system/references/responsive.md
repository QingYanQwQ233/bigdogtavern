# 响应式

## 三档断点

| 断点 | 名称 | 导航 | 内容 |
|---|---|---|---|
| ≥ 961 | 桌面 | 常驻侧栏 | 两栏（列表 + 详情并列） |
| 641–960 | 平板 | 抽屉 | 两栏 |
| ≤ 640 | 移动 | 抽屉 | **单栏切换**（list ⇄ detail） |

**规则：断点改变的是行为，不是结构。** 同一个出口控件在三档里都在同一个逻辑位置（区域头部左侧），只有点下去之后的落点不同。当前桌面端和移动端各写一套 head、同类出口两处维护，这是债。

## 移动端单栏切换

移动端由 `dataset.mobilePanel` 承载 list / detail 两态：

- `list` 态：显示列表列，详情列隐藏
- `detail` 态：显示详情列，列表列隐藏，出口标签变成 `‹ 返回X`

这里的出口行为正是 `data-nav-up` 的语义：**详情态的 Up 目标是列表，不是上一级视图**。写新面板时必须沿用这套状态机（`setMobileManagerPanel()` 等），不要自己造。

## 触控命中区

| 元素 | 最小尺寸 |
|---|---|
| 主要操作按钮 | 44 × 44 |
| 列表行 / 导航项 | 宽度撑满，高度可窄（见例外） |
| 表单控件 | 44 高 |
| 移动端表单控件字号 | ≥ 16px（防 WebView 聚焦缩放） |

**已知例外**：`nav-item` 高度约 33–36px，是**有意做窄**的产品决定，不算债。任何自动化检查都必须把它列为白名单，不要"修好"它。

**已知偏差**：设置弹窗内 29 个控件里有 27 个小于 44px（表单输入 316×37、页签 58×33、导入/导出按钮 74×28、复选框 16×16）。这部分留给 UI 改版处理，已登记在 `docs/ui-beauty-declaration.md §7` 的「当前已知偏差」表里。

## 空间分配原则

- **主内容优先获得空间**：对话正文应该吃掉所有剩余宽度，不要让工具栏抢
- **侧栏宽度固定，内容宽度弹性**：列表列通常固定宽度（约 260–320），详情列 `flex: 1`
- **不要用 `position: fixed` 承载主要内容**：移动端键盘弹起时会遮挡
- 长文本一律 `overflow-wrap: anywhere` + `white-space: pre-wrap`，不要靠 `overflow: hidden` 掩盖

## 安全区

Android WebView 上要注意：

- 底部输入框要避开系统手势区 / 导航条
- 键盘弹起会改变视口高度，用 `dvh` 而不是 `vh`，或监听 `visualViewport`
- 横向不要产生滚动条（`overflow-x: hidden` 是兜底，不是解决方案）
