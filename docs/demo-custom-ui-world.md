# 雨幕协议 · 自定义界面实验室

> **历史兼容实验，勿作为新卡模板。** 这份示例保留了已退休的直接 MVU 与 action 演示；当前游玩态扩展不能直接写 Runtime。新卡请改用 [RPG 卡从零教程](rpg-card-tutorial.md) 第 17.9 节的完整 custom 页面，通过数据绑定和 choose 提交玩家行动。

文件：`demo-custom-ui-world.tavern-world.json`

这张世界卡专门演示完整的 `ui.layout: "custom"`：它把宿主 RPG 的顶部信息、左右侧栏、状态栏、叙事区、快捷选项、输入框和覆盖层全部声明为 `hide`，并通过 `ui.shell` 隐藏宿主应用导航和顶栏，改由卡内 HTML/CSS/JS 在隔离 iframe 中统一绘制。卡内左侧状态、中央消息、右侧协议面板、选项和输入组成唯一可见工作区。

导入方法：打开“世界与存档” → “导入世界包” → 选择该 JSON → 确认导入 → 创建存档 → 授权扩展。

可以依次检查：

- 进入存档后是否直接接管工作区，宿主 RPG 同级侧栏、应用导航、顶栏和底部输入是否都不再出现；
- 右上角“进入浏览器全屏”是否能请求浏览器全屏并隐藏上级导航；浏览器拒绝时仍会保留卡内界面；
- “退出沉浸”或 `Esc` 是否退出浏览器全屏并恢复窗口化卡内界面；“返回世界库”是否通过通用桥回到世界库；
- “AI 终端”是否能从卡内打开宿主调试终端；发送行动时状态栏应显示请求中、提交成功或错误原因；
- 左侧 `data-tavern-bind` 是否显示存档名称、位置、信号强度和协议状态；
- 中央唯一的 `data-tavern-messages` 消息流是否由当前回合驱动，并把 Markdown（标题、段落、列表、引用、代码块）渲染出来；
- 底部卡内输入框是否能提交自由行动；
- “MVU · 切换巡航”是否写入 `signal=7 / mode=巡航`；
- “Action · 发送脉冲”是否调用声明式 runtime action，使信号强度 +1；
- 点击宿主应用导航中的“世界与存档”可返回世界库；退出沉浸不会删除或复制消息、状态和存档。

这张卡的 `ui.layout` 设为 `custom`，`ui.shell.navigation/topbar` 设为 `hide`，`extension.immersive` 设为 `false`（不强制自动浏览器全屏），用于验证导入即接管、浏览器全屏、显式退出、Esc、返回世界库、单一消息流和卡内桥接按钮。旧卡若同时保留 `data-tavern-narrative` 与 `data-tavern-messages`，桥接会默认隐藏前者；只有显式添加 `data-tavern-allow-duplicate="true"` 才保留双视图。
