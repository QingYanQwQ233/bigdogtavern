# RPG 制卡工作台改造讨论稿

> 状态：**首个切片已实施。** 2026-08-26 已确认并实现“表单优先，保留折叠的高级兼容区”。这不是新的运行时契约；已发布世界卡和已有存档不会因本次改造被自动修改。

## 任务范围

- 来源：2026-08-26 用户需求——“RPG 卡制作的优化，制卡进入单独页面，不再需要写 JSON，而是填表；可以有全局变量，比如物品耐久，使用了多少次就减少多少耐久。”
- 目标用户：制作 RPG 世界卡的作者。
- 目标：把当前混合式世界草稿弹窗升级为独立的、表单优先的制卡工作台，并让作者能用界面声明存档状态、物品与动作。
- 非目标：不把 AI 叙事正文当作状态来源；不引入可执行脚本；不悄悄改写已发布世界卡或任一存档。

## 已核实的底座

1. 现有 `/api/world-drafts` 已提供草稿、乐观并发、发布前检查与不可变世界版本；新工作台应复用它，而不是另建保存链。
2. `runtime` 已有受限 DSL：变量、集合、动作、可用条件和声明式效果都会在一次世界回合中原子校验并写入当前 `WorldSave`。
3. 耐久无需新增后端契约：物品集合可声明 `durability` 与 `uses` 字段；“使用”动作可要求 `durability > 0`，然后执行 `durability - N`、`uses + 1`。耐久归零时动作被拒绝，不会产生半提交。
4. `runtime.scope` 当前只是定义元数据，所有 runtime 值都随各自 `WorldSave` 保存。因此首期的“全局变量”应命名为**存档全局变量**：它对本局全部动作可见，但不跨不同存档共享。

## 已确认的首期设计

### 页面与路由

- 从世界库进入 `?worldDraft=<id>` 可直达、可刷新的全屏作者页，而不是普通弹窗；草稿读取、保存、发布、检查与乐观并发全部复用现有 API。
- 浏览器刷新同一作者页时按草稿 ID 恢复；关闭、返回与未保存修改会保留确认提示。
- 常规界面维持现有资料区，并把“状态与物品”提升为独立的表单区；发布仍沿用现有不可变版本流程。

### 表单与数据映射

| 作者表单 | 生成/维护的既有 DSL | 首期边界 |
|---|---|---|
| 存档全局变量 | `runtime.variables` 的 number/string/boolean 项 | 默认 `scope: "save"`；复杂 list/map/json 留在高级兼容区 |
| 耐久物品 | `runtime.collections` 中的 `durable-items` 条目 | 条目包含稳定 ID、名称、耐久、最大耐久、已使用次数 |
| 使用动作 | 每件物品一个 `runtime.actions` 项 | 有 `durability > 0` 前置条件；使用后按固定值扣耐久、使用次数 +1 |
| 高级兼容区 | 同一份 `runtime` 原始配置 | 仅显式展开/载入后覆盖表单，未表单化或不完整的条目保持原样 |

表单不会另存第二份 runtime 数据。保存时由表单合并回 `world.runtime`，保留未知变量、集合和动作；表单管理的稳定 ID 不会被自动改名，以免升级中的耐久值重置。

表单创建的耐久物品表、固定使用动作和可见变量会在**未声明 `ui.sidebar`** 时获得宿主侧栏的默认只读/操作投影，因此新作者无需再填写 `ui.sidebar.panels`。为保持移动端与手写侧栏相同的上限，自动面板最多 24 个，优先保留耐久表和使用动作；超出时请声明手写 `ui.sidebar`。一旦世界卡声明 `ui.sidebar`（包括 `panels: []`），就完全按手写配置显示；高级 JSON 中空的或缺少固定使用动作的 `durable-items` 集合不会被表单接管或改写。

### 兼容、安全与恢复

- 已发布版本与已有存档继续钉住原始世界版本；编辑后仍按当前草稿发布流程生成新版本。
- 已有世界卡的原始字段不丢失。复杂、尚未有安全表单模型的字段不能被表单静默覆盖。
- 首期不假装支持动态“按输入数量扣耐久”、从一个通用动作任选物品，或跨存档共享变量；前两者需要扩展动作模板契约，后者需要新的持久化和并发契约。
- 表单编辑既有 runtime 时必须稳定保留变量、集合、物品和动作 ID；改变它们会使升级中的既有运行态无法沿用。

## 首期验收

- 作者可不写 JSON 创建变量、物品和“使用后耐久 -1”的动作；每件物品产生固定 ID 的使用动作。
- 新建卡不填写 `ui.sidebar` 时，玩家仍能看到可见变量、耐久/使用次数及可用的固定使用按钮；声明手写侧栏后不会混入自动面板。
- 耐久为 1 的物品使用一次后为 0；再次使用被可用性检查拒绝，不写入半个状态更新，也会作为不可用动作告知 Agent。
- 保存与刷新后的草稿会恢复表单和 Runtime；复杂 enum/list/map/json 变量、未表单化集合和动作留在高级 JSON 中。
- 已以独立临时数据目录的真实浏览器流程验证：打开直达页、变量/物品编辑、保存、刷新恢复、JSON 兼容、窄屏无横向溢出与退出路由。
